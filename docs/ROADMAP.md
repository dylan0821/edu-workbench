# 教培工作台后续演进计划（大班直播 & 多客户端）

> 记录时间：2026-11-24  
> 适用项目：教培工作台（Teaching Workbench v0.2.0）

本文档梳理当前系统在**公网部署后**，面向**大班多人直播**与**多客户端（桌面端、微信小程序、移动端）**扩展的技术选型、约束条件与分阶段实施计划。

---

## 一、大班多人直播演进计划

### 1. 当前架构瓶颈
- 现有内置实时课堂基于浏览器 **WebRTC P2P（Mesh）** 架构：老师端需要向每一位在线学生单独推一路音视频/屏幕共享流。
- **适用边界**：1 对 1 及 **10 人以内小班互动/答疑**表现良好；当单节直播课达到 **20–50+ 人** 时，教师端上行带宽与 CPU 编码压力会成为明显瓶颈。

### 2. 可选技术路线对比

| 方案 | 承载人数 | 开发成本 | 运维 / 费用 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **方案 1：外接成熟课堂**（ClassIn / 腾讯会议 / Zoom 等） | 30–300+ 人 | 零开发（现已支持） | 按第三方平台计费 | 急需开大班课、不想自运维音视频 |
| **方案 2：自建开源 SFU（LiveKit）** | 50–300 人 | 低–中（替换 RTC 层） | 云服务器 + 按流量计费带宽 | 全流程留在自有系统、成本可控、支持 Web / 桌面 / App |
| **方案 3：商用 RTC 云（腾讯云 TRTC / 声网）** | 100–1000+ 人 | 低–中（接入 SDK） | 按分钟/人数计费 | 弱网抗丢包要求极高、或需**同步打通微信小程序实时上课** |

### 3. 推荐改造路径（以 SFU / RTC 升级为例）
- **保留现有业务层不动**：多页白板、上课/下课状态机、开课前 10 分钟限制、学生红点提示、举手排队、讨论区、悬浮互动小窗、权限隔离全部复用。
- **仅替换音视频传输层**：
  1. 后端 `src/server.js` 新增房间鉴权 Token 签发接口（校验本课授课教师 / 在读学生权限后签发）。
  2. 前端 `public/js/views/classroom.js` 将原生 `RTCPeerConnection` 替换为 `livekit-client` 或 `trtc-js-sdk`，教师只推 1 路流，服务器负责 1 对 N 分发。
  3. 录制能力可平滑升级为服务端录制（如 LiveKit Egress / TRTC 云端混流录制），减轻教师浏览器压力。
- **带宽成本建议**：自建 SFU 时优先选择云厂商**按流量计费（高带宽峰值如 100Mbps）**，避免为非上课时间购买昂贵的固定大带宽。

## 二、多客户端扩展计划（桌面端 / PWA / 微信小程序 / App）

### 1. 架构复用基础
当前后端已是标准前后端分离的 **REST JSON API**，鉴权与数据隔离均在服务端完成，所有新客户端可直接共用同一套后端与 SQLite 数据库。

### 2. 服务端前置通用改造（供小程序与 App 接入）
在开发微信小程序或原生 App 前，建议先完成以下两项轻量级后端升级：
1. **鉴权兼容 `Bearer Token`**：
   - 保留现有 Web 端 `HttpOnly Cookie (wb_session)`。
   - 鉴权中间件增加读取 `Authorization: Bearer <token>`（直接复用现有 `sessions` 表，无需重构账号体系）。
2. **实时通道兼容 WebSocket**：
   - Web 与桌面端继续使用 `SSE (EventSource)`。
   - 为不支持原生 `EventSource` 的微信小程序补一层轻量 WebSocket 网关，把现有 `broadcastQa`（课程群 / 开课红点）与 `broadcastRoom`（白板 / 举手 / 讨论）事件同步下发。

### 3. 各客户端定位与实施要点

#### A. 桌面客户端（macOS / Windows）—— 优先面向教师与管理员
- **技术方案**：使用 **Electron** 或 **Tauri** 封装现有 Web 端。
- **核心收益**：
  - 几乎零业务重写，1–2 天即可出包。
  - 解决浏览器端限制：提供**系统级始终置顶的悬浮互动小窗**（不受画中画手势限制）、更纯净的屏幕共享体验及全局快捷键。

#### B. 移动端 PWA（iPad / 手机浏览器）—— 几乎零成本
- **技术方案**：补充 `manifest.json` 与图标配置。
- **核心收益**：学生和家长可将工作台「添加到主屏幕」全屏打开，满足日常查课表、看录播、课程群交流与拍照交作业。

#### C. 微信小程序 —— 优先面向学生与家长留存
- **适合优先落地的模块（高价值、低阻力）**：
  - 课表查看 + **微信服务通知 / 订阅消息开课提醒**
  - 拍照/相册快捷提交作业与查看教师批改评语
  - 录播回放观看与学习进度同步
  - 课程群实时答疑、公告与 `@提醒`
- **关键约束与避坑点**：
  - **域名备案**：微信小程序要求后端接口为已备案的 `https://` 域名。
  - **实时音视频限制**：小程序不支持标准浏览器 WebRTC，若需在小程序内直接实时连麦，须使用微信 `<live-pusher>` / `<live-player>`（通常配合 **腾讯云 TRTC 小程序 SDK**），且需要**企业主体 + 在线教育/教培类目审核**（个人主体无法开通）。
  - **务实策略**：小程序一期聚焦教务、提醒、作业、录播与课程群；直播课先引导通过浏览器/外接课堂进入，待后续接入 TRTC 后再补齐小程序内实时连麦。

#### D. iOS / Android 原生 App —— 后期按需考虑
- 中小教培早期不建议单独维护双端原生 App（审核周期长、维护成本高）；待业务规模扩大后，可基于 `uni-app`、`Capacitor` 或 `Flutter` 复用同一套后端接口构建。

## 三、分阶段实施路线图

### Phase 1：公网基础落地 + 教师桌面体验升级
- [ ] 部署至云服务器，配置域名 + HTTPS（Caddy / Nginx）及 `coturn` TURN 服务。
- [ ] 配置 `pm2` / `systemd` 进程守护与 `data/` 定期异地备份。
- [ ] 视需要封装教师端 **macOS / Windows 桌面客户端（Electron / Tauri）**，强化共享屏幕与置顶互动小窗体验。

### Phase 2：多端接口适配 + 学生/家长端微信小程序（V1）
- [ ] 后端支持 `Authorization: Bearer <token>` 鉴权兼容。
- [ ] 后端新增轻量 WebSocket 实时推送通道（同步课程群与开课状态）。
- [ ] 开发学生/家长端微信小程序（课表、微信开课提醒、作业拍照提交、录播回放、课程群）。
- [ ] 为 Web 端补充 PWA `manifest.json`，优化 iPad / 手机主屏体验。

### Phase 3：大班多人实时直播升级（全端统一音视频）
- [ ] 根据是否需要小程序内直接连麦，在 **LiveKit（自建低成本）** 与 **腾讯云 TRTC（全端含小程序最佳兼容）** 中确定音视频底座。
- [ ] 后端新增房间 Token 签发接口，前端 `classroom.js` 替换 P2P 为 SFU SDK。
- [ ] （可选）接入服务端/云端录制，替代浏览器本地合流录制，进一步提升大班直播与回放稳定性。
